	\textbf{Authentication.} the process of verifying a claimed identity. (Prove who you are.)\\
	\textbf{Passwords.} secret shared between user and system.\\
	\textit{Problems}:
	\begin{itemize}[leftmargin=10px]
		\item[I  ] \textbf{Secure transfer.} password may be eavesdropped when communicated.\\
		      \textit{Encrypting makes password unreadable to eavesdropper, but still allows copy and send.} (\warning \textbf{Replay-Attacks.} sending same request without needing the password)\\
		      \textbf{Challenge-Response} protocol solves this.
		      \begin{enumerate}[leftmargin=10px]
			      \item Principal declares they want to login.
			      \item System authenticating principal sends a \textbf{Challenge} (a random value).
			      \item Principal encrypts password \textit{together} with the challenge.(ensures password is never encrypted with same value and encryption is fresh)
			      \item After checking password, System \textit{must} delete the challenge.
		      \end{enumerate}

		\item[II ] \textbf{Secure check.} naïve checks may leak information about the password.\\
		      \textbf{Check Options:}
		      \begin{enumerate}[leftmargin=10px]
			      \item Letter by letter - Time to check leaks the number of correct checked letters. (Timing channel)
			      \item Check everything - Same time regardless of input (hashing solves this by default).
		      \end{enumerate}

		\item[III] \textbf{Secure storage.} if stolen entire system is compromised.\\
		      Passwords must be stored to be checked against but \textit{not stored in clear} $\rightarrow$ an adversary can read them and impersonate users.\\
		      \textbf{
			      Storage Options :}
		      \begin{enumerate}[leftmargin=10px]
			      \item Encrypted Passwords. requires key to be stored in same system as database, not secure.
			      \item Hashed Passwords. Not a solution, hashing does \textbf{not} require a key. \warning passwords are not truly random.$\rightarrow$Database can be downloaded and compared against hash of most common passwords (\textbf{Dictionary Attack)}.
			      \item Hashed + Salted Passwords (Do this !). \textbf{Salt.} unique random value generated per password. \textbf{We store}: $(\text{username}, H('123456'||\text{salt}_n), \text{salt}_n)$. \\ Dictionary attacks are still possible but same passwords are undetectable.\\
			            \textit{Principal} asks to login$\rightarrow$\textit{System} sends Challenge$\rightarrow$\textit{Principal} sends encrypted password with Challenge $\rightarrow$\textit{System} checks Challenge, decrypts, looks up hash by username, hashes plaintext with salt and checks if same as stored.
		      \end{enumerate}

		\item[IV] \textbf{Secure passwords.} easy-to-remember passwords tend to be easy to guess
	\end{itemize}

	\textbf{Biometrics.} measurement and statistical analysis of people's unique physical characteristics(fingerprint, face, \ldots).
	\hline
	\textbf{Biometrics Authentication.}
	\begin{enumerate}[leftmargin=10px]
		\item \textbf{Enrollment.} biometric is captured by a sensor and processed to be converted in a stream of bits(Biometric Template). \textbf{Capture} $\rightarrow$ \textbf{Process} $\rightarrow$ \textbf{Store}.
		\item \textbf{Verification.} biometric is captured, processed and compared against the stored one. \textbf{Capture} $\rightarrow$ \textbf{Process} $\rightarrow$ \textbf{Compare}. (threshold for match vs. no match).\\ Balance between False Positives (wrongly authenticated) and False Negatives(wrongly rejected).
	\end{enumerate}
	Storing / Processing can happen locally($\oplus$ privacy) / remotely($\oplus$ security).
	\hline
	\textbf{Authentication Tokens.} by proving ownership of a token. (Smart Card, \ldots)
	\begin{enumerate}[leftmargin=10px]
		\item Offline - Device and Server establish a common \textit{seed} (random value) \& synchronize their clocks.
		\item When Device wants identity:
		      \begin{enumerate}[leftmargin=7px]
			      \item[(a)] Server asks to prove it. (b) They both compute $n=\frac{{now} - start}{interval}$. \textit{Current interval.}
			      \item[(c)] Device applies \textbf{keyed} function (pre-shared key) n times on initial seed. $v=f^n(seed)$
			      \item[(d)] Device sends result to Server. (encrypted, eavesdropper can't have the seed).
			      \item[(e)] Server computes same value and checks against the one received.
		      \end{enumerate}
	\end{enumerate}
	Can't be a hashing function (hash functions aren't keyed!, eavesdropper could compute $h_k(seed)$ for any k after the one observed.).

		\textbf{Security Engineering process.}\\
		1.Define security policy \textit{(principals, assets, properties)} and a threat model. 2.Define security mechanisms that support policy of threat model. 3.Build implementation to support the mechanisms
	\end{minipage}
	\hfill
	\begin{minipage}[t]{0.39\textwidth}
		\textbf{Attack Engineering process.} \\exploit weaknesses introduced during the security engineering process due to lack of careness/knowledge or errors.
	\end{minipage}\\
	\textbf{Threat Modelling.} process to identify threats / unprotected resources.
	\begin{itemize}
		\item[-] \textbf{Attack Trees.} represent goal as the root and ways to achieve it as branches.
		\item[-] \textbf{STRIDE.} 1) Identify assets, principals, trust boundaries, and named flows \textbf{2) For each threat:} \\
		      1. STRIDE category, 2.what changes/abuse happens, 3.which flow it affects, 4.concrete mitigation.\\
		      \textbf{Spoofing:} fake identity (user/service). \textbf{Tampering:} unauthorized edit of data/messages/code.\\
		      \textbf{Repudiation:} deny action (no provable record). \textbf{Info disclosure:} leak confidential data/metadata.\\
		      \textbf{Denial of service:} exhaust/block resources/reduce availability. \textbf{Elevation of privilege:} gain higher privileges than allowed.
		\item[-] \textbf{PASTA.} start from buisness goals, processes, and use cases. Find threats in buisness model, assess impact, prioritize on risk.
	\end{itemize}

	\textbf{Methods.}\\
	- \textbf{GET.} requests a resource; parameters are appended to the URL as query key–value pairs after "?", separated by `\&`.\\[-7px]
	\[
		\underbrace{\texttt{http://}}_{\text{protocol}}
		\underbrace{\texttt{www.mywebsite.com}}_{\text{hostname / domain}}
		\underbrace{\texttt{/apparel}}_{\text{directory}}
		\underbrace{\texttt{/skirt.php}}_{\text{filename}}
		\underbrace{\texttt{?sku=123\&lang=en\&sect=silk}}_{\text{query parameters}}
	\]
	\begin{minipage}[t]{0.44\textwidth}
		- \textbf{POST.} creates or updates a resource; sends data in the request body (not the URL) and typically modifies server data.\\
		\texttt{POST /test/demo\_form.php HTTP/1.1}\\
		\texttt{Host: w3schools.com}\\
		\texttt{name1=value1\&name2=value2}
	\end{minipage}\hfill\begin{minipage}[t]{0.54\textwidth}
		\textbf{Cookies.} small piece of data stored by browser on client (creates HTTP "sessions"). \textit{also used to track users.}. \textbf{Ambient Authority} is used with cookies.
		\textit{logged into bank.com $\rightarrow$ cookies stored for bank.com. \textbf{Any} (!CSRF) new HTTP requests to this website \textbf{will include all cookies} to continue session}.
	\end{minipage}		\\[2px]
	\textbf{URL.} standardized address that specifies a resource’s access method, host, and path.\\
	\textbf{HTML.} markup language using tags to structure content and tell browser how to render a webpage.\\
	\textbf{WEP.} Wi-Fi security protocol that encrypts frames with \textbf{RC4} (stream cipher with random 24-bit IV). IV repeats frequently, causing keystream reuse and enabling message (and sometimes key) recovery.\\
	\textbf{PHP.} server-side scripting language for dynamic web pages; uses variables and request/session data (`\$\_{gateway}ET`, `\$\_POST`, `\$\_SESSION`) and outputs HTML with `echo`.\\
	\textit{Lifetime of a GET/POST request.}\\
	1. Browser sends HTTP GET/POST request.\\ 2. Web Server receives requests and identifies if it's a static asset(.jpg,\dots) or dynamic(.php).\\
	3. PHP interpreter executes called .php 4. Sends response to web browser

	\begin{minipage}[t]{0.49\textwidth}
		\textbf{Data Execution Prevention (DEP).} Mark memory pages as writable OR executable, never both. (prevents code injection by making stack/heap non-executable)\\
		\includegraphics[width=0.75\textwidth]{assets/dep.png}\\
		$\oplus$ low-overhead/hardware enforced \\$\ominus$ no self-modifying code.
	\end{minipage}\hfill
	\begin{minipage}[t]{0.49\textwidth}
		\textbf{Code Reuse - Control Flow Hijack.} Bypass DEP by chaining existing executable code (gadgets) instead of injecting new code.\\
		\textbf{Attack Chain:}
		\begin{enumerate}[leftmargin=10px]
			\item \textbf{Memory Safety Violation.} \texttt{strcpy} writes past \texttt{tmp[MAX]} (spatial error)
			\item \textbf{Integrity (*C).} Attacker overwrites return address and adjacent stack data
			\item \textbf{Location (\&C).} Return address points to \texttt{\&system()}, stack contains \texttt{\&"/bin/sh"}
			\item \textbf{Usage (*\&C).} CPU dereferences corrupted pointer, jumps to \texttt{system()}
			\item \textbf{Gadget Chaining.} Existing code (\texttt{system()}) executes with attacker-controlled arguments, no shellcode needed
		\end{enumerate}
	\end{minipage}
\end{minipage}

	\textbf{Common Weaknesses Enumeration (CWE).} database of software errors leading to vulnerabilities.
	\begin{enumerate}[leftmargin=10px]
		\item \textbf{CWE 1 - Insecure Interaction Between Components.} unchecked information sent between different components.
		      \begin{enumerate}[leftmargin=10px]
			      \item \textbf{CWE 78 - OS Command Injection.} application embeds unvalidated user input into an OS command, allowing attackers to execute arbitrary commands \textit{ls /home/$user}.

			      \item \textbf{CWE 79 - Cross Site Scripting.} application embeds unvalidated user input into dynamically generated web content, causes browser to execute injected scripts.\\
			            \textbf{Common Script Injections.}\\
			            \texttt{<img src=x onerror=alert(1)>;}
			            \texttt{<svg onload=alert(1)>;}\\
			            \texttt{<body onload=alert(1)>;}
			            \texttt{<a href=javascript:alert(1)>text</a>;}\\
			            \textbf{Useful Functions.}\\
			            \begin{minipage}[t]{0.45\textwidth}
				            \texttt{navigator.userAgent}\\
				            Returns the browser identification string; increases fingerprinting surface.\\
				            \textit{Chrome/143.0.0.0 Mobile Safari/537.36}\\
				            \texttt{window.location.replace(url)}\\
				            Forces navigation to \texttt{url} without adding a history entry.\\
				            \texttt{document.cookie}\\
				            Returns all non-\texttt{HttpOnly} cookies for the current origin; exposed session/state cookies immediate account compromise on XSS.
			            \end{minipage}\hfill
			            \begin{minipage}[t]{0.45\textwidth}
				            \texttt{document.domain}\\
				            Gets/sets legacy origin relaxation; can broaden trust across subdomains and weaken same-origin isolation.\\
				            \texttt{document.referrer}\\
				            Returns the referrer URL when sent; can leak sensitive paths/parameters without strict Referrer-Policy.\\
				            \texttt{document.URL}\\
				            Returns the full current document URL
			            \end{minipage}
			      \item \textbf{CWE 362 - Cross Site Request Forgery.} malicious website makes a state-changing action using user’s session cookie for another website.\\
			            \fbox{
				            \begin{minipage}[htp]{0.9\textwidth}
					            \textbf{Same Origin Policy (SOP).} web browser security mechanism that restricts scripts from one origin from reading data from another origin. An origin is a (protocol, host, port) \textit{http:\/\/example.com}. \\
					            \textit{This doesn't prevent CSRF as it's based on sending a request and that the browser naturally attaches cookies of the destination domain in request (unless special setting).}
				            \end{minipage}}\\
			            \textbf{Solutions:}\\
			            For every state-changing endpoint:\\
			            - Check Origin header and only allow exact origin.\\
			            - If Origin missing, require Referer and ensure it starts with expected origin, else reject.\\
			            \textit{Keep GET side-effect free; Require a CSRF token (challenge) on every state-changing request; For high-riks actions require re-auth.}
		      \end{enumerate}
		\item \textbf{CWE 2 - Risky Ressource Management.} not properly managed creation, usage, transfer, or destruction of important system resources

		\item \textbf{CWE 3 - Porous Defenses.} defensive techniques misused, abused, or just ignored
	\end{enumerate}

	\textbf{Software Security.}\\[-7px]
	\begin{minipage}[htp]{0.47\textwidth}
		\textbf{Stack.} Call frames: locals, args, return addresses; grows down.\\
		\textbf{Heap.} Dynamic allocations via \texttt{malloc/new}; grows up.\\
		\textbf{Uninitialized data (BSS).} Global/static zero-initialized storage; zeroed at program start.\\
		\textbf{Initialized data.} Global/static with explicit initial values; loaded from the executable.\\
		\textbf{Text.} Executable code (often read-only); mapped from the executable.\\
		\textbf{Args \& env.} \texttt{argv}/environment strings placed at startup near the initial stack.
	\end{minipage}

	\begin{minipage}[t]{0.44\textwidth}
		\textbf{Memory Corruption.} \\Unintended modification of memory location due to missing / faulty safety checks.
		\begin{cc}
			void vuln(int user1, int*array){
					// no bound check for user1
					array[user1] = 42;}
		\end{cc}
	\end{minipage}\hfill
	\begin{minipage}[t]{0.55\textwidth}
		\textbf{Memory Safety - Temporal Error.} tried access to memory initially reserved for our program but not reserved anymore.
		\begin{cc}
			void vulnerable(char* buf) {
					free(buf); // variable was freed.
					buf[12] = 42;}
		\end{cc}
	\end{minipage}\\
	\begin{minipage}[t]{0.39\textwidth}
		\textbf{Memory Safety - Spatial Error.} \\tried access to memory outside the bounds of the allocated region.
		\begin{cc}
			void vulnerable(){
					char buf[12];
					char *ptr = buf[11];
					*ptr++=10;
					// out of allocated memory
					*ptr=42;}
		\end{cc}
	\end{minipage}\hfill
	\begin{minipage}[t]{0.59\textwidth}
		\textbf{CWE 134 - Uncontrolled Format String.} \\inject format specifiers that can leak memory contents in untrusted input string.\\
		"\%4\$p":Reads 4th parameter even if doesn't exist\\
		"\%6\$n":Write to address \textbf{pointed to} by 6th parameter
		\begin{cc}
			int main(int argc, char** argv){
					char buffer[100];
					strncpy(buffer.argv[1]);
					printf(buffer);
					return 0;}
		\end{cc}
	\end{minipage}\\
	\begin{minipage}[t]{0.49\textwidth}
		\textbf{Code Injection Attack.} \\
		\textbf{1.} Control unchecked variable. \\
		\textbf{2.}Overwrite return address. \textbf{3.}Hijack control flow.
		\textbf{4.} Arbitrary code execution.
		\begin{cc}
			void vuln(char* u1){
					// strlen(u1) < MAX?
					char tmp[MAX];
					strcpy(tmp, u1);...
				} vuln(&exploit);
		\end{cc}
	\end{minipage}
	\begin{minipage}[t]{0.49\textwidth}
		\textbf{Attack Chain:}\\
		1. \textbf{Memory Safety Violation.} \texttt{strcpy} writes past \texttt{tmp[MAX]} (spatial error)\\
		2. \textbf{Integrity (*C).} Attacker overwrites return address on stack\\
		3. \textbf{Location (\&C).} Return address now points to shellcode\\
		4. \textbf{Usage (*\&C).} CPU dereferences corrupted pointer\\
		5. \textbf{Code Injection.} Shellcode executes with program privileges
	\end{minipage}
	\hline
	\begin{minipage}[t]{0.49\textwidth}
		\textbf{Address Space Layout Randomization (ASLR).}\\
		Loader/OS randomizes memory regions(code/stack/heap/libraries) at load time. Same code, different addresses on each run. (prevents target addresses prediction/breaks gadgets)\\
		\textit{Limitations:}
		1.Probabilistic defense, not deterministic.
		2.Vulnerable to addresses leaks. \\3.Some regions remain static \textit{x86}.\\
		4.Performance overhead.(requires the system
		to keep track of all pointers)
		\hline
		\textbf{Mitigation.} A defense mechanism that prevents or reduces the impact of attacks.\\
		Properties:\\
		1. \textbf{Effectiveness.} must prevent/defend attacks\\
		2. \textbf{Efficiency:} low comp/memory overhead\\
		3. \textbf{Compatibility:} easy deployment (no major software/hardware changes)\\
		\textit{Examples: Sandboxing. isolates process from system resources and other processes. \\DEP, ASLR, Stack canaries.}
	\end{minipage}\hfill
	\begin{minipage}[t]{0.49\textwidth}
		\textbf{Stack Canaries.}\\
		Compiler places random secret value between local buffers and return address. Checked before function returns and abort if corrupted. \\
		\textit{(detects buffer overflows before control hijack)}\\[-12px]
		\begin{center}
			\includegraphics[width=0.7\textwidth]{assets/stack-canaries.png}
		\end{center}
		\textit{Limitations:} \\
		1.Probabilistic, vulnerable to canary leaks.\\
		2.No protection against targeted writes (jumps over canary).\\
		3.No protection against reads.\\
		4.Performance overhead from checks.
	\end{minipage}

	\begin{minipage}[t]{0.49\textwidth}
		\textbf{Error.} difference between observed behavior and specified behavior (a violation of underlying spec)\\
		\textbf{Testing.} executing a program to find bugs/errors and test security properties.\\
		\textit{Ideally}, complete test of all:
		\begin{itemize}
			\item[-] \textbf{Control-flows.} all path of program.
			\item[-] \textbf{Data-flow.} all values used at each location.
		\end{itemize}
	\end{minipage}\hfill\vline\hfill
	\begin{minipage}[t]{0.5\textwidth}
		\textbf{Manual Testing.}\\
		designed by human heuristic(intuition).\\
		-	\textbf{Exhaustive.} cover all input (not feasible)\\
		- \textbf{Functional.} cover all requirements (depend on specification)\\
		- \textbf{Random.} automate test generation (incomplete)\\
		- \textbf{Structural.} cover all code (unit testing)
	\end{minipage}\\
	Practice is limited by \textit{state explosion} (impossible to test everything.).\\
	\begin{minipage}[htp]{0.51\textwidth}
		\textbf{Automated Testing.} decided algorithmatically\\
		\textit{(run program/find bugs/enforce properties).}
		\begin{itemize}[leftmargin=4pt, labelsep=1pt]
			\item[-] \textbf{Static analysis.} analyse program without executing it. (imprecise)
			\item[-] \textbf{Symbolic analysis.(doesn't scale)} converts program to logical equations covering many executions, provides full path coverage(complete). Path explosion: each branch doubles paths$\rightarrow$exponential blowup.
			\item[-] \textbf{Dynamic analysis.} \textit{fuzzing} inspect program by executing it (hard to cover all paths)
		\end{itemize}
	\end{minipage}\hfill
	\begin{minipage}[htp]{0.47\textwidth}
		\textbf{Coverage.} testing metric. software flaw can only be detected if flawed statement is executed $\Rightarrow$ effectiveness of a test suite depends on how many statements are executed.
		\begin{itemize}
			\item[-] \textbf{Statement Coverage.} Measures how many statements (e.g., assignments, comparisons, etc.) in the program have been executed by the test suite.
			\item[-] \textbf{Branch Coverage.} Measures how many branches among all possible execution paths have been executed by the test suite.
		\end{itemize}
	\end{minipage}\\
	\begin{minipage}[t]{0.49\textwidth}
		\textbf{Fuzzing.} random testing that mutates input to improve test coverage ($\oplus$scales very well). \\
		\textit{State-of-the-art fuzzers use coverage as feedback to guide input mutations.} \textbf{Types of Fuzzing:}\\
		1.\textbf{Dumb Fuzzing:} not aware of input structure; randomly mutates input without guidance.\\
		2.\textbf{Generation-based Fuzzing:} uses model describing valid inputs; generates new input seeds in each round based on model specifications.
	\end{minipage}\hfill
	\begin{minipage}[t]{0.49\textwidth}
		3. \textbf{Mutation-based Fuzzing:} uses set of valid seed inputs; modifies inputs based on feedback from previous rounds. Mutations can be informed by program structure:\\
		\textbf{White-box} (full access to code/internal logic)\\
		\textbf{Grey-box} (partial knowledge, typically coverage feedback only)\\
		\textbf{Black-box} (no internal knowledge, input/output observation only)
	\end{minipage}\\
	\textbf{Symbolic Execution with Fuzzing.} Whitebox fuzzing uses \textit{Symbolic Analysis} to generate new seed inputs for unexplored paths when random mutation gets stuck, improving coverage.
	\hline
	\begin{minipage}[t]{0.28\textwidth}
		\textbf{Sanitization.} detect bugs by enforcing policies, \textbf{increasing testing effectiveness.}\\
		- Assertions\\
		- Segmentation faults\\
		- Division by zero traps\\
		- Uncaught exceptions\\
		- Mitigations triggering termination\\
		\textit{cannot detect logic bugs/specification, only bugs that violate specific policy}
	\end{minipage}\hfill\vline\hfill
	\begin{minipage}[t]{0.31\textwidth}
		\textbf{Address Sanitizer (ASan).}\\
		Detects memory errors by placing red zones around objects and checking them on trigger events. It can detect:\\
		-Out-of-bounds accesses to heap, stack, and globals\\
		-Use-after-free\\
		-Use-after-return (config.)\\
		-Use-after-scope (configurable)\\
		-Double-free and invalid free\\
		-Memory leaks (experimental)\\
		\textbf{Performance.}+ 2$\times$ slowdown.
	\end{minipage}\hfill\vline\hfill
	\begin{minipage}[t]{0.38\textwidth}
		\textbf{Undefined Behavior Sanitizer (UBSan).} \textit{(only one usable in production.)}\\Detects undefined behavior by instrumenting code to trap on typical C/C++ undefined behavior:
		- Unsigned/misaligned pointers\\
		- Signed integer overflow\\
		- Conversion between floating point types leading to overflow\\
		- Illegal use of NULL pointers\\
		- Illegal pointer arithmetic\\
		\textbf{Performance.} slowdown depends on amount/frequency of checks.
	\end{minipage}
	\hline
	\begin{minipage}[htp]{0.52\textwidth}
		\textbf{Network Security Properties.}\\
		-\textbf{Naming Security.} association between lower level names \textit{(network addresses)} and higher level names \textit{(Alice)} must not be influenced by adversary. \textit{(Integrity, Authenticity, Availability[naming service])}\\
		-\textbf{Routing Security.} route over network and delivery of messages must not be influenced by adversary.\textit{(Integrity, Authenticity, Availability, Authorization)}\\
		-\textbf{Session Security.} messages within the same session cannot be modified (keep ordering and no adding/removing messages) \textit{(Integrity, Authenticity)}.
	\end{minipage}\hfill
	\begin{minipage}[htp]{0.46\textwidth}\vspace*{-10px}
		\includegraphics[width=1\textwidth]{assets/layers.png}
	\end{minipage}\\
	- \textbf{Content Security.} content of messages must not be readable or influenced by adversaries \textit{(Confidentiality, Integrity, Authenticity)}.
	\hline
	\textbf{IP Address.} 4-byte address (IPv4), network.host.\\
	\textbf{Subnet Mask.} Used to determine network portion of IP address via bitwise AND operation.\\
	\textbf{Gateway.} Router IP address used to forward packets to different subnets.\\
	\textbf{ARP (Address Resolution Protocol).} translates IP addresses $\to$ MAC addresses. Each host maintains cache table of IP $\leftrightarrow$ MAC mappings. If not available, broadcast ARP request.
	\begin{itemize}[leftmargin=4px]
		\item[] 		\textbf{ARP Packet Format.} ($\warning$ No integrity checks nor authentication in ARP packets)\\
		      \begin{minipage}[htp]{0.55\textwidth}
			      \textbf{HTYPE} (2 bytes): Hardware type (1 = Ethernet/Wi-Fi)\\
			      \textbf{PTYPE} (2 bytes): Protocol type (0x0800 = IPv4)\\
			      \textbf{HLEN} (1 byte): Hardware address length (6 for MAC)\\
			      \textbf{PLEN} (1 byte): Protocol address length (4 for IPv4)\\
			      \textbf{OPERATION} (2 bytes): 1 = Request, 2 = Reply
		      \end{minipage}\hfill
		      \begin{minipage}[htp]{0.45\textwidth}
			      \textbf{Sender HA}: MAC address of sender\\
			      \textbf{Sender PA}: IP address of sender\\
			      \textbf{Target HA}: MAC of target (zero in Request, filled in Reply)\\
			      \textbf{Target PA}: IP address being queried
		      \end{minipage}
		\item[] \begin{minipage}[htp]{0.46\textwidth}
			      \textbf{ARP Spoofing Attacks.}
			      \textit{(Naïve threat model assuming insiders are trustworthy.)}\\
			      \textbf{Man-in-the-Middle.} Attacker convinces both parties their MAC is the other's MAC \\$\rightarrow$ intercept/modify all traffic\\
				      \textbf{Denial of Service.} Provide wrong MAC mappings $\rightarrow$ victims cannot receive packets\\
			      \textbf{Resource Theft.} Impersonate others to bypass bandwidth limits or steal allocated resources
		      \end{minipage}\hfill\vline\hfill
		      \begin{minipage}[htp]{0.5\textwidth}
			      \textbf{ARP Defenses}:\\
			      \textbf{Static ARP entries.} Manually configure critical mappings \textit{(gateway)} in read-only cache\\
			      \textbf{Spoofing detection.} Monitor for inconsistencies\\(one IP$\rightarrow$multiple MACs/one MAC$\rightarrow$multiple IPs)\\
			      \textbf{Cross-checking.} Verify mappings with multiple hosts before trusting\\
			      \textbf{Change alerts.} Email admin when IP-MAC associations change, require human confirmation
		      \end{minipage}
	\end{itemize}
	\textbf{IP Routing.} \textbf{Input:}($IP_{source}$, $IP_{dest}$, Subnet Mask $M$, $IP_{gateway}$) \; \textbf{Output:} Packet sent to destination\\
	\begin{minipage}[t]{0.48\textwidth}
		\begin{enumerate}[leftmargin=6pt,labelsep=0pt,itemsep=0pt,series=mainenum]
			\item Compute $(IP_{source} \land M)$ and $(IP_{dest} \land M)$
			\item \textbf{If} $(IP_{source} \land M) = (IP_{dest} \land M)$ (same subnet):
			      \begin{enumerate}[leftmargin=4pt,labelsep=0pt,itemsep=0pt]
				      \item \textbf{If} MAC address of $IP_{dest}$ is in ARP cache: Send packet to $IP_{dest}$ using cached MAC
				      \item \textbf{Else}:
				            \begin{enumerate}[leftmargin=4pt,labelsep=0pt,itemsep=0pt]
					            \item Broadcast ARP request: ``Who has $IP_{dest}$?''
					            \item Wait for ARP reply with MAC address
					            \item Cache mapping $IP_{dest} \leftrightarrow MAC$
					            \item Send packet to $IP_{dest}$ using MAC address
				            \end{enumerate}
			      \end{enumerate}
		\end{enumerate}
	\end{minipage}\hfill\vline\hfill
	\begin{minipage}[t]{0.5\textwidth}
		\begin{enumerate}[leftmargin=4pt,labelsep=0pt,itemsep=0pt,resume=mainenum]
			\item \textbf{Else} (different subnet):
			      \begin{enumerate}[leftmargin=4pt,labelsep=0pt,itemsep=0pt]
				      \item \textbf{If} MAC address of $IP_{gateway}$ is in ARP cache: Send packet to gateway using cached MAC
				      \item \textbf{Else}:
				            \begin{enumerate}[leftmargin=4pt,labelsep=0pt,itemsep=0pt]
					            \item Broadcast ARP request "Who has $IP_{gateway}$?"
					            \item Wait for ARP reply with gateway MAC
					            \item Cache mapping $IP_{gateway} \leftrightarrow MAC$
					            \item Send packet to gateway using MAC address
				            \end{enumerate}
				      \item Gateway forwards packet through WAN
			      \end{enumerate}
		\end{enumerate}
	\end{minipage}\hline
	\begin{minipage}[t]{0.48\textwidth}
		\textbf{DNS (domain name service).} translates human-readable domain names into IP addresses.\\
		\textit{Query initiation:} Client sends DNS query to recursive resolver (typically ISP-provided)\\
		\textit{Cache check:} Resolver first checks its cache for existing resolution\\
		\textit{Hierarchical resolution (if not cached):} Resolver queries in sequence:
		\begin{enumerate}[leftmargin=6pt, labelsep=0pt, itemsep=0pt]
			\item Root server (directs to appropriate TLD)
			\item Top-Level Domain (TLD) server \textit{(.com)}
			\item Authoritative name server (holds actual domain-to-IP mapping)
		\end{enumerate}
		\textit{Response propagation:} Resolver returns IP address to client\\
		\textit{Connection:} Client uses resolved IP to connect to destination host\\
		\textit{Distributed database:} DNS mappings stored across hierarchical servers globally
	\end{minipage}\hfill\vline\hfill
	\begin{minipage}[t]{0.50\textwidth}
		\textbf{DNS Spoofing Attacks.} \textit{(DNS lacks authentication and integrity protection.)}\\
		\textbf{Cache Poisoning.} inject fake (domain, IP) pairs into resolver's cache $\Rightarrow$ all clients querying resolver get malicious IP\\
		\textbf{DNS Hijacking.} Intercept/modify DNS responses in transit (man-in-the-middle) $\rightarrow$ victim receives attacker-controlled IP\\
		$\Rightarrow$ DoS/redirection to malicious hosts/MITM monitoring
		\hline
		\textbf{DNS Spoofing Defenses}:\\
		\textbf{DNSSEC.} Authoritative servers sign DNS responses $\Rightarrow$ prevents cache poisoning by verifying origin authenticity (no confidentiality)\\
		\textbf{DNS-over-HTTPS (DoH).} Tunnel DNS queries over HTTPS connection $\rightarrow$ (confidentiality/integrity/authenticity)\\
		\textbf{DNS-over-TLS.} \\Encrypt DNS traffic using TLS protocol\\
	\end{minipage}
\end{minipage}
\begin{minipage}[t]{0.49\textwidth}
	\begin{minipage}[t]{0.455\textwidth}
		\textbf{Border Gateway Protocol (BGP).} make routing tables between Autonomous Systems (AS) with independent routing domains\\
		1.Routers maintain tables of \\\textbf{(IP subnet$\rightarrow$Router IP, cost)} \textit{(no integrity/no authenticity)}\\
		2.Routes change constantly due to faults, new contracts, infrastructure updates\\
		3.BGP selects lowest-cost routes (real money considerations)\\
		$\warning$ Weak Authentication using short shared secrets (up to 80 ASCII bytes) and MD5-based MAC $\Rightarrow$ only prevents DoS, not route integrity
	\end{minipage}
	\begin{minipage}[t]{0.52\textwidth}
		\textbf{BGP Hijacking Attacks.}
		Adversary controls/compromises router, injects false low-cost routes\\
		$\rightarrow$ attracts traffic to adversary path and false routes propagate until expiration\\
		$\Rightarrow$\textit{Surveillance, injection/modification, censorship, DoS}.  \textbf{\textit{modifies route, not destination}}
		\hline
		\textbf{BGP Hijacking Defenses}:\\
		\textbf{Route filtering.} Block geographically implausible routes ($\warning$limited effectiveness)\\
		\textbf{Challenge:} No central authority for route correctness\\
		$\Rightarrow$ \textbf{BGPsec.} AS certificates link keys to IP blocks; updates require authoritative AS signature
	\end{minipage}\hline
	\textbf{Internet Protocol (IP).} Enables addressing and routing of packets between hosts\\
	\begin{minipage}[t]{0.49\textwidth}
		\textbf{No protection:} No integrity/authentication for source/destination addresses, no confidentiality for data (only non-cryptographic checksum for transmission errors)\\
		\textbf{IP Spoofing Attacks.}\\
		\textbf{Impersonation:} Fake identity to steal resources\\
		\textbf{Man-in-the-Middle:} Monitor, modify, or deny communication\\
		\textbf{DoS:} Spoof source IP to trigger servers sending packets to victim\\
		\textit{Note:} May require TCP hijacking for full MitM
	\end{minipage}\hfill\vline\hfill
	\begin{minipage}[t]{0.49\textwidth}
		\textbf{IPSec Defenses.} Cryptographic security at IP level\\
		\textbf{Key exchange:} Public key or pre-shared symmetric keys\\
		\textbf{AH:} Authentication \& integrity (HMAC), replay protection (sequence numbers)\\
		\textbf{ESP:} Adds confidentiality on top of auth\\
		\textbf{Transport mode:} Protects payload, keeps original headers\\
		\textbf{Tunnel mode:} Protects entire packet (headers + payload) inside new packet
	\end{minipage}\hline
	\begin{minipage}[t]{0.52\textwidth}
		\textbf{Virtual Private Network (VPN).}\\
		Uses IPSec tunnel mode to create private network over public internet\\
		\textbf{Properties:} Appears as single network, internal routing, full packet protection (confidentiality, authentication, integrity, replay)\\
		\textbf{Configuration 1:} Connect two LANs securely\\
		\textbf{Configuration 2:} Exit local network from different point (VPN as a Service $\rightarrow$ change apparent IP)\\
		\textbf{IP rewriting necessity:} VPN rewrites return address to its own; otherwise replies bypass VPN tunnel, breaking encryption
	\end{minipage}\hfill\vline\hfill
	\begin{minipage}[t]{0.46\textwidth}
		\textbf{VPN Limitations.}\\
		\textbf{Does NOT protect against:}\\
		- DoS attacks (IP still exists)\\
		- Application-layer authentication issues\\
		\textbf{VPN vs Proxy:}\\
		\textit{VPN:} End-to-end encryption, acts as one network, no MitM\\
		\textit{Proxy:} Encryption only end-to-proxy, separates two networks, proxy sees both sides (acts as MitM)\\
		Both hide IP from receiver but offer different security properties
	\end{minipage}
